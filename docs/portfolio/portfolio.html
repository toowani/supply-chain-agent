3. 판정: 근거로 걸러내고, 애매하면 사람에게

LLM은 권고문에서 "어떤 API를, 어떤 입력으로, 어떤 플랫폼에서 써야 터지는가"만 뽑습니다. 권고문에 없는 함수명은 버리고, 인용은 원문과 일치하는지 검사합니다. 코드는 그 패키지를 import하는 파일에서만 조건 API를 찾습니다. 서비스 코드와, 그 패키지를 쓰는 의존 패키지의 설치 소스까지 봅니다.

not_affected 근거 규칙: 조건 API 미참조 40건, 플랫폼 제외 5건, 사람 결정(데모) 반영 4건. 조건 API가 코드에 있거나 조건 없이 버전만 맞으면 affected, 결정할 근거가 없으면 보류(사람 검토)입니다.

그룹 SI에서의 가치

  • 계열사마다 다른 스택을 하나의 서비스–부품 그래프로 봅니다. 공유 부품 99개처럼 겹치는 부품은 판단과 조치를 한 번에 냅니다.

  • 판정 근거를 OpenVEX로 표준화해, 그룹에서 검증한 뒤 고객사·협력사와 공유합니다.
  • EU CRA 보고 의무(2026.09 적용, 전면 2027.12)처럼 SBOM과 대응 이력을 요구하는 규제에 재스캔·VEX 기록으로 대응합니다.

7. 산출물 예시와 한계

티켓 초안 예시 (out/tickets/T01-upgrade-pypi-pillow.md 머리말)

[T01] 업그레이드 pypi:pillow 11.3.0 → 13.0.0

  • 조치: 업그레이드 pypi:pillow 11.3.0 → 13.0.0
  • 대상 서비스: podcast4life
  • 담당팀: 미디어서비스팀
  • 위험 감소량: 11.545 (전체 잔여 위험 25.481 중 45.3%, 앞선 티켓과 겹치는 행 제외)
  • 호환성 위험: 메이저 버전 변경(11.3.0 → 13.0.0) — 변경 내역·테스트 확인 필요 · Python 런타임 업그레이드 필요(Python 3.9.6 → >=3.11)
  • 비고: podcast4life: 목표 버전은 Python >=3.11 필요, 서비스는 3.9.6 → 런타임 업그레이드 필요

이어서 요약·영향·작업 단계(LLM 서술), 해소 취약점 표, 근거(권고문 인용·file:line), 검증 명령, 승인·기각 명령이 붙습니다.

OpenVEX 예시 (out/vex.json, 3쪽 사례)

"vulnerability": {"name": "CVE-2026-115924"},
"products": [{"@id": "pkg:pypi/rembg@2.0.61"}],
"status": "not_affected",
"justification": "vulnerable_code_not_in_execute_path",
"impact_statement": "The vulnerable API named in the advisory is not referenced by the product's code."

전체 156건: under_investigation 106, not_affected 43, affected 7.

개발·검증 방식

구현은 Claude Code로 했고, 구현과 분리된 검증 에이전트가 네 차례 원시 데이터에서 숫자를 다시 계산하고 코드·제출물을 감사했습니다(docs/verification.md). 검증 에이전트도 AI이므로 독립된 제3자 검증은 아닙니다.

회차대상찾고 고친 것
1차scan·ingest·graph·score174행 점수·순위 독립 재계산 일치, 분류·중복 결함 4건 수정
2차judge·plan·feedback·report·eval모듈별 리뷰 에이전트가 버그 13건 수정, 주요 4건 회귀 테스트
3차KPI·판정 안전성·조치·유출·문구not_affected 오판 경로 6가지 수정(규칙 v4), 런타임 호환성 검사 추가
4차제출물 전체(심사·사실·공개·코드)비평 71건(high 13) 반영, 재검증 지적 6건 수정, 캐시 없이 재실행

재현성: LLM 캐시를 지우고 전체를 다시 돌리면 판정 164/174건이 같았습니다.

한계

  • 파일럿은 본인 레포 5개입니다. KEV 등재 경고가 0건이라 KEV 가중의 효과는 이번 데이터에서 드러나지 않았습니다.
  • 정답셋 56건 중 affected가 2건으로 클래스 균형이 맞지 않습니다. 라벨은 AI 초안 2회(56건) + 테스트셋 본인 검수 진행 중, 튜닝셋 36건은 AI 초안만입니다.
  • 보류율이 67.2%로 높습니다. 그중 87건이 콜그래프 필요(전이·의존 경로) 범주(의존 패키지 경유 63, 전이 24)라 콜그래프 연동이 다음 과제입니다.
  • 테스트셋에서 놓친 위험은 0건이지만 표본이 작아 놓칠 가능성을 배제하지 못합니다. 그래서 보수 모드를 실행 옵션으로 둡니다.
